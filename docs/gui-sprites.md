# GUI sprites

Widget sprites for the planned GUI system. They are 1.21 **GUI sprites**: PNGs under
`assets/mmdlib/textures/gui/sprites/`, loaded into the GUI atlas automatically and drawn with
`GuiGraphics.blitSprite(ResourceLocation.parse("mmdlib:<name>"), x, y, width, height)`. A
sprite's `.mcmeta`, where present, tells `blitSprite` how to stretch it. The fill gauge uses
plain textures instead; see [gauge textures](gauge-textures.md).

All of them are generated by `scripts/generate_gui_sprites.py` (standard library only) and
match the agreed machine-screen mockup. Greyscale sprites are meant to be tinted.

## Sprites

| Sprite | Size | Scaling | Use |
|---|---|---|---|
| `slot` | 18×18 | nine-slice, border 1 | Item slot, tintable; stretch for large slots (26×26 output) and side-configuration faces |
| `group` | 16×16 | nine-slice, border 1 | Grouping boundary: thin recessed panel, tintable (faint blue inputs, faint orange outputs) |
| `panel` | 16×16 | nine-slice, border 4 | Vanilla-style screen background at any size |
| `side_tab` | 34×16 | nine-slice, border 3 | Tab growing out of a panel's right edge, e.g. the upgrade column |
| `compact_frame` | 8×8 | nine-slice, border 1 | Frame of the compact segmented gauge; transparent middle (see [gauge textures](gauge-textures.md#compact-segmented-gauge)) |
| `checkbox`, `checkbox_selected` | 10×10 | none | Recessed checkbox, unchecked / checked |
| `radio`, `radio_selected` | 10×10 | none | Bevelled circle: raised when off, pressed in when selected |
| `progress_arrow`, `progress_arrow_filled` | 24×16 | none | Progress indicator, empty / full |
| `upgrade_speed`, `upgrade_energy`, `upgrade_capacity` | 16×16 | none | Outline shown in an empty upgrade slot |
| `icon_sides` | 16×16 | none | White cube icon for the side-configuration button |

Buttons use vanilla's own `minecraft:widget/button` sprites (and their highlighted and disabled
versions), so resource packs restyle them; MMDLib ships no button sprite.

## Tinting

Tinting multiplies colours, so it can only darken. White reproduces the untinted look.

```java
static void tinted(GuiGraphics g, ResourceLocation sprite, int x, int y, int w, int h, int rgb, float alpha) {
    g.setColor(((rgb >> 16) & 0xFF) / 255F, ((rgb >> 8) & 0xFF) / 255F, (rgb & 0xFF) / 255F, alpha);
    g.blitSprite(sprite, x, y, w, h);
    g.setColor(1F, 1F, 1F, 1F); // always reset, or everything drawn after is tinted too
}
```

Mockup colours: upgrade slots `0xF0CD82`; input group `0xE1E9FF`; output group `0xFFE8D6`.
Upgrade outlines are drawn at 45% opacity over their slot.

## Placement

- **Slot**: the item renders at `(x + 1, y + 1)` for an 18×18 slot, matching a vanilla `Slot`
  positioned there; for a 26×26 slot it renders centred at `(x + 5, y + 5)`. Grids are 18 px apart.
- **Side tab**: draw the panel first, then the tab at `(panelX + panelWidth - 4, y)`, 34 wide and
  any height of at least 7. Its column 3 lands on the panel's outline column; columns 0–2 cover
  the panel's border so both share one background, and transparent pixels let the panel's own
  shadow show where the bevels meet. The tab's usable inside starts at `panelX + panelWidth`.
- **Progress arrow**: draw `progress_arrow`, then the left `round(24 * progress)` columns of
  `progress_arrow_filled` with the cropping overload
  `blitSprite(sprite, 24, 16, 0, 0, x, y, filledWidth, 16)`.
- **Side configuration**: faces are `slot` stretched to 20×20, tinted with the face's mode colour,
  laid out in a 3×3 grid: Top above Front; Left, Front, Right across; Bottom below Front with Back
  beneath Right. The mode letter and any neighbour's item icon are drawn on top.
- **Player inventory**: unless a screen says otherwise, it ends with the standard player inventory:
  three rows of nine `slot`s, a 4 px gap, then the hotbar row.

## Asset validation

`scripts/validate_static_assets.py` accepts `.mcmeta` files declaring either `animation`
(animated textures) or `gui` (sprite scaling: `nine_slice`, `tile`, or `stretch`).
